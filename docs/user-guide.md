# 使用指南

提交: beb3400

## 本地运行

安装 Python 3.12、uv、Node.js、pnpm 与 just，然后执行：

```bash
just setup
just dev
```

浏览器打开 `http://127.0.0.1:5173`。首次使用先创建媒体库，填写现有影片目录，再扫描。

创建媒体库时同时选择主分类：`Japan`、`China`、`Korea`、`Europe` 或 `Other`。主分类来自用户的
目录规划，不由可能误判的番号反推；现有名称为“国产”、Japan、Europe 等的媒体库会自动迁移到对应分类。

## Docker

```bash
cp .env.example .env
MEDIA_PATH=/path/to/media docker compose up -d --build
```

容器内媒体根目录是 `/media`。创建媒体库时应使用容器路径，而不是宿主机路径。

## 识别方式

- 有番号的 JAV：文件名保留番号，例如 `SSIS-123.mp4`。
- FC2、HEYZO 与无码日期号：支持常见文件名格式。
- 国产长尾或无番号内容：用标题搜索，或把作品详情页 URL 填入人工识别框。
- 欧美场景：配置 ThePornDB Token 后可使用 oshash；也可用标题、来源 URL 或 provider ID。
- 不确定结果：候选停留在审核队列，确认后才创建正式作品。

扫描首先生成可追溯的 `local-path` 本地作品，因此即使在线来源暂时不可用，命名明确的现有媒体也不会全部
堆在待确认。标题优先使用文件名；`V (1)`、`v2`、纯数字、`1(16)` 等通用名称会逐级查找最近的有效目录。
例如 `Dragon's (@DragonLLLLL) 推特合集/V (2).strm` 会建成 `DragonLLLLL_2`；
`有码/河北彩花/[SONE-118]/SONE-118A.strm` 与 B 分段会按番号合并为同一 Japan 作品，并把河北彩花作为目录演员线索。

本地建档不冒充在线刮削结果。标准番号作品可在“作品库”点击“刷新元数据”，精确候选会合并到原作品并补充
正式标题、片商、演员、标签和封面。来源超时或无结果时保留本地作品，不会退回待确认。

公开网页可能出现地区限制、登录要求或反自动化挑战。来源失败会单独记录，不会阻断其它来源；项目不尝试绕过访问控制。

## STRM 文件

媒体库会扫描 `.strm`。文件应是 UTF-8、带 BOM 的 UTF-16 或 GB18030 文本，首个非空、非注释行是媒体地址；
单文件上限 64 KiB。支持 HTTP(S)、RTSP、SMB、`plugin://`、绝对路径和相对路径等常见定位符。

扫描只读取 `.strm` 文本，不连接播放地址，不下载媒体，也不把播放地址当作详情页刮削。
文件名是 `001.strm` 之类通用名称时，会尝试使用目标 URL 的文件名或父目录作为标题。
保存到数据库和界面展示的地址会移除账号、密码、签名参数和 URL 片段。

## 网络磁盘

- Windows 可填写已连接的盘符路径（如 `Z:\媒体`）或 UNC 路径（如 `\\server\share\媒体`）。
- 服务进程必须能使用相应共享凭据；浏览器当前用户能访问并不代表后台服务账号也能访问。
- Linux/macOS 和 Docker 应先把 NFS/SMB/WebDAV 挂载为本地目录，再把挂载路径添加为媒体库。
- 只读共享可以扫描和识别；移动、复制、整理与写 NFO 需要写权限。
- 断开的子目录会出现在扫描错误列表中，不会丢弃已经扫描成功的资产。操作系统级网络超时仍可能使一次目录访问等待较久。

## 无番号别名

“媒体库”页面的“无番号别名规则”可以维护三组 JSON 映射：`studios`、`series` 和 `actors`。
键是文件名或目录里可能出现的别名，值是希望保存的规范名称。保存后重新扫描即可更新线索，例如：

```json
{
  "studios": {"杏吧原创": "杏吧传媒"},
  "series": {"小宝": "小宝探花"},
  "actors": {"人物别名": "规范姓名"}
}
```

匹配最长别名并去重。别名只增加候选评分和内容族路由，模糊结果仍留在审核队列。
如果所有在线来源都没有结果，可在待确认资产上输入更准确的标题后点击“本地候选”，再检查并接受该候选完成离线建档。

## 垃圾文件过滤

“媒体库”页面的“垃圾文件过滤词”按每行一个普通关键词维护。扫描器只对支持的视频和 `.strm`
检查规则，匹配范围是媒体库内的完整相对路径，因此文件名或任一父目录命中都会过滤。匹配不区分大小写，
并忽略关键词及路径中的空白差异；英文单词按文件名分词匹配，`Example` 不会因包含 `sample` 字母片段而被过滤。

初始规则包含常见直播/裸聊广告文案，并补充 `sample`、`trailer`、`preview`、试看、预告片、
防走失、最新地址、公众号和 APP 推广等高置信规则。保存后写入
`data/filter-words.txt`，下次扫描生效。过滤只是不入库，不删除、移动或改写原始文件；扫描完成后的
“过滤”数量与不支持扩展名的“跳过”数量分开显示。

已经入库后才新增的过滤规则也会在下次扫描生效：资产标记为 `ignored` 并从默认列表隐藏，但原始媒体和已有
审计记录不会被删除。

## 整理与 NFO

“媒体库”页提供五种批量输出模式：

- 当前文件夹：不复制或移动视频，为视频或 `.strm` 写同名 `.nfo`。
- 复制到新路径：保留源文件，在目标作品库复制媒体并写 NFO。
- 移动到新路径：把媒体移入目标作品库并同步数据库路径。
- 硬链接到新路径：不重复占用文件数据；源和目标必须位于支持硬链接的同一文件系统。
- 软链接到新路径：建立指向源媒体的链接；Windows 可能需要开发者模式或链接权限。

后四种模式必须填写已存在的目标根目录，可使用 `{category}`、`{actor}`、`{studio}`、`{code}`、
`{code_or_title}`、`{family}`、`{year}`、`{part}` 和 `{ext}` 目录模板。每次先“预览计划”，检查数量、目标和冲突，
再显式确认执行。媒体目标永不覆盖；已有 NFO 可选择覆盖、跳过或报错。NFO 通过临时文件原子替换，
内容兼容 Kodi、Jellyfin 与 Emby 常用 movie NFO 字段。

整理器识别 `CD2`、`PART2`、`v2`、`-B` 和番号后的尾部单数字分片；模板未使用 `{part}` 时会自动在
目标视频名追加 `-CDn`，避免多段落到同一文件。媒体同目录的 `.srt`、`.ass`、`.ssa`、`.vtt`、`.sub`
按番号和分片配对，并使用相同的移动/复制/链接方式。无番号的 `Dragon_1`、`Dragon_2` 不会被误认为同一作品分片。

## 按番号建档与图片

“作品库”页可以直接输入番号查询，不要求先扫描本地视频。精确同番号的多个来源会聚合成一个作品：主结果提供
标题等标量，其余来源补齐剧情、日期、片商等空字段，并合并演员、标签和图片；标量字段来源保存在数据库中。

作品已有图片 URL 后可点击“缓存图片”。缓存按 URL 哈希去重，只接受常见图片 MIME，单图默认最大 25 MiB，
并拒绝 localhost、私网 IP 和 `.local` 地址。缓存成功后，整理计划会把首张封面复制为
`影片名-poster.jpg/png/webp`；已存在的封面默认跳过，不阻断视频和 NFO。

## 在线来源与代理

“在线来源诊断”会用一个已知番号实际请求各个已配置来源，区分成功、无结果、连接超时、HTTP 拦截和未配置。
若所在网络无法直连 JavDB/JavBus，在 `.env` 中配置代理并重启：

```dotenv
SHADOW_MDC_PROXY_URL=http://127.0.0.1:7890
SHADOW_MDC_REQUEST_TIMEOUT_SECONDS=20
SHADOW_MDC_REQUEST_RETRIES=1
```

代理地址只从服务端环境读取，不通过浏览器或诊断响应回传。重试仅用于连接错误、超时、429 和 5xx；来源失败
不会覆盖本地已识别作品。

## 运行记录

“运行记录”保存最近的扫描、番号查询、图片缓存和批量整理结果，包含处理范围、成功/部分完成状态、数量统计和
完成时间。当前是同步操作的持久审计历史，不冒充后台队列；页面请求关闭时不可依赖它继续执行。后续后台 Worker
会沿用同一任务实体增加阶段进度、重试与取消。

## 数据边界

Shadow MDC 只管理用户已有本地媒体的元数据与公开图片，不提供影片下载、磁力搜索、破解、登录绕过或在线播放。
