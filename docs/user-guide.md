# 使用指南

## 本地运行

安装 Python 3.12、uv、Node.js、pnpm 与 just，然后执行：

```bash
just setup
just dev
```

浏览器打开 `http://127.0.0.1:5173`。首次使用先创建媒体库，填写现有影片目录，再扫描。

创建媒体库时不需要选择主分类。扫描器逐文件自动判定：JAV 只接受成功提取的标准番号或专用编号；目录中的
`JAV`、`Japan`、日本、有码和无码只是结构标签，不参与无番号内容分类。其它无番号内容再结合附近目录中的
国产、麻豆、探花、韩国、欧美等关键词和标题文字特征分类，不使用媒体库名把内容强制归为 JAV。

## Docker

```bash
cp .env.example .env
MEDIA_PATH=/path/to/media docker compose up -d --build
```

容器内媒体根目录是 `/media`。创建媒体库时应使用容器路径，而不是宿主机路径。

## 识别方式

- 有番号的 JAV：文件名保留番号，例如 `SSIS-123.mp4`。
- FC2、HEYZO 与无码日期号：支持常见文件名格式。
- 国产长尾或无番号内容：用标题搜索，或把作品详情页 URL 填入人工识别框。
- 欧美场景：配置 ThePornDB Token 后可使用 oshash；也可用标题、来源 URL 或 provider ID。
- 不确定结果：候选停留在审核队列，确认后才创建正式作品。

扫描先保存可追溯的 `local-path` 候选。标题优先使用文件名；`V (1)`、`v2`、纯数字、
`1(16)` 等通用名称会逐级查找最近的有效目录。例如
`Dragon's (@DragonLLLLL) 推特合集/V (2).strm` 会得到 `DragonLLLLL_2` 识别线索。执行“识别并优化媒体”时，
无番号文件先按这个标题搜索在线来源；没有可接受结果时自动形成 China 分类的本地作品。
`有码/河北彩花/[SONE-118]/SONE-118A.strm` 与 B 分段会提取同一番号，一次查询命中后关联到
同一个 Japan/JAV 作品，并把河北彩花作为目录演员线索。

媒体库卡片的“识别并优化媒体”会分别按规范化番号和优化标题去重查询，并优先轮转到最久未处理的资产。
有番号作品只有精确候选达到自动接受阈值才进入作品库，失败继续待确认；无番号作品在线无可接受结果后按本地
标题、演员和自动分类入库。界面会分别报告“在线识别”和“本地优化”数量。

公开网页可能出现地区限制、登录要求或反自动化挑战。来源失败会单独记录，不会阻断其它来源；项目不尝试绕过访问控制。

## STRM 文件

媒体库会扫描 `.strm`。文件应是 UTF-8、带 BOM 的 UTF-16 或 GB18030 文本，首个非空、非注释行是媒体地址；
单文件上限 64 KiB。支持 HTTP(S)、RTSP、SMB、`plugin://`、绝对路径和相对路径等常见定位符。

扫描只读取 `.strm` 文本，不连接播放地址，不下载媒体，也不把播放地址当作详情页刮削。
文件名是 `001.strm` 之类通用名称时，会尝试使用目标 URL 的文件名或父目录作为标题。
保存到数据库和界面展示的地址会移除账号、密码、签名参数和 URL 片段。

## 网络磁盘

- Windows 可填写已连接的盘符路径（如 `Z:\媒体`）或 UNC 路径（如 `\\server\share\媒体`）。
- 服务进程必须能使用相应共享凭据；浏览器当前用户能访问并不代表后台服务账号也能访问。
- Linux/macOS 和 Docker 应先把 NFS/SMB/WebDAV 挂载为本地目录，再把挂载路径添加为媒体库。
- 只读共享可以扫描和识别；移动、复制、整理与写 NFO 需要写权限。
- 断开的子目录会出现在扫描错误列表中，不会丢弃已经扫描成功的资产。操作系统级网络超时仍可能使一次目录访问等待较久。

## 无番号别名

“媒体库”页面的“无番号别名规则”可以维护三组 JSON 映射：`studios`、`series` 和 `actors`。
键是文件名或目录里可能出现的别名，值是希望保存的规范名称。保存后重新扫描即可更新线索，例如：

```json
{
  "studios": {"杏吧原创": "杏吧传媒"},
  "series": {"小宝": "小宝探花"},
  "actors": {"人物别名": "规范姓名"}
}
```

匹配最长别名并去重。别名增加候选评分和内容族路由；无番号在线无结果时也用于规范本地作品信息。
“演员库”以 Actor 与 Work 的多对多关系汇总演员、创作者别名、分类和关联作品，并展示演员代表图与作品海报。已知演员名会在下一次扫描时自动加入演员别名匹配，
辅助识别通用文件名所在目录。演员知识独立保存在 `data/actor-catalog.json`，新作品只做合并；清理扫描、候选、
任务或测试作品数据库不会删除演员库。仍可在待确认资产上输入更准确标题或创建人工候选进行纠错。

非 JAV 演员和独立创作者使用单独的 `data/non-jav-actors.json` 词库，不会混入上述 JAV 演员作品库。词库保存
规范姓名、别名、平台分组、地区分类和允许自动匹配的安全名称，可用
`python scripts/import_non_jav_actors.py <名单.txt>` 从 Markdown/CSV 混合名单重新整理生成。扫描时它只作为本地
路径和文件名的演员证据，不会把无番号内容误标为 JAV。

前端“演员库 → 非 JAV 演员名单”直接管理这份词库，可维护规范名称、别名、分组、分类、简介和备注，并上传
本地头像；头像保存在 `data/actor-images/`。 词库条目可通过 `image_file` 指向该目录中的文件（上传接口使用姓名 NFKC casefold 的 SHA-256 加扩展名）。若没有可复用的真人照片，可运行 `python scripts/seed_non_jav_placeholders.py` 生成带姓名缩写的 identicon 头像（欧美词条会尝试 Wikipedia 公开缩略图）；之后可在演员库中上传替换。待确认页面的“确认多级目录的演员”可以从当前叶子目录向上选择
真正的演员层级，并把演员应用到所选目录及全部子目录，规则保存到 `data/directory-actors.json`。演员以下的
目录层级会参与标题和标签：例如 `江南第一深情/旧版/短 黑t妹妹/IMG_0940` 会生成标题
`江南第一深情-旧版-短黑t妹妹-IMG_0940`，并写入 `探花`、`旧版`、`短黑t妹妹` 等标签。以后该目录新增的
`1`、`2`、`3`、`V1` 等数字或分段文件会自动按同一层级规则生成本地作品，不再进入待确认。选择更高层级时会
替换其下旧的叶子规则，避免后续扫描重新套用错误演员。已在演员名单中登记、且目录组件与规范名称或
安全别名完全一致时，上述数字分段也可在首次扫描时自动处理。

## 垃圾文件过滤

“媒体库”页面的“垃圾文件过滤词”按每行一个普通关键词维护。扫描器只对支持的视频和 `.strm`
检查规则，匹配范围是媒体库内的完整相对路径，因此文件名或任一父目录命中都会过滤。匹配不区分大小写，
并忽略关键词及路径中的空白差异；英文单词按文件名分词匹配，`Example` 不会因包含 `sample` 字母片段而被过滤。

初始规则包含常见直播/裸聊广告文案，并补充 `sample`、`trailer`、`preview`、试看、预告片、
防走失、最新地址、公众号和 APP 推广等高置信规则。保存后写入
`data/filter-words.txt`，下次扫描生效。普通扫描只是不入库，不删除、移动或改写原始文件；扫描完成后的
“过滤”数量与不支持扩展名的“跳过”数量分开显示。使用“移动到新路径”时是唯一例外：预览计划会明确列出
源目录中待删除的过滤文件和空目录。只有当目录除本次已移动媒体、空子目录及过滤文件外不含其它内容时，
执行后才会删除这些过滤文件并从内到外清理空目录；媒体库根目录永远保留。

已经入库后才新增的过滤规则也会在下次扫描生效：资产标记为 `ignored` 并从默认列表隐藏，但原始媒体和已有
审计记录不会被删除。

## 每库识别范围

每个媒体库都有独立的“处理范围”：`全部内容` 保持 JAV、国产、韩国、欧美及无番号内容的完整处理；
`仅 JAV` 只把内容族识别为 JAV 的文件送入批量在线识别和整理计划。范围外文件仍保留扫描记录，切回
“全部内容”即可继续处理，不会被错误归入 JAV，也不会在仅 JAV 模式下被移动。

待确认、作品库和演员库页面顶部提供关键词与自动分类展示筛选；媒体库页面可按名称、路径和处理范围筛选。
这些控件只隐藏当前页面中不匹配的条目，不修改数据库，也不影响扫描、识别或整理范围。

## 整理与 NFO

作品元数据和实际媒体文件分开保存。同一番号换成 4K、HEVC 或不同音轨版本时，重新扫描会直接关联已有作品，
保留标题、演员、剧情和图片，只刷新文件自身的分辨率、编码、帧率、码率、HDR、音频和实际时长。
这些质量字段会显示在文件线索中，并写入 NFO 的 `fileinfo/streamdetails`。

“媒体库”页提供五种批量输出模式：

- 当前文件夹：不复制或移动视频，在作品目录写 `movie.nfo` 和已抓取图片。
- 复制到新路径：保留源文件，在目标作品库复制媒体并写 NFO。
- 移动到新路径：把媒体移入目标作品库并同步数据库路径；按预览计划清理仅含过滤文件的空源目录。
- 硬链接到新路径：不重复占用文件数据；源和目标必须位于支持硬链接的同一文件系统。
- 软链接到新路径：建立指向源媒体的链接；Windows 可能需要开发者模式或链接权限。

后四种模式必须填写已存在的目标根目录。默认模板为
`{group}/{subgroup}/{actor}/{folder_name}/{media_name}.{ext}`，JAV 会整理为
`JAV/有码/演员/[番号] 标题/番号.ext`。此外可使用 `{category}`、`{studio}`、`{code}`、
`{code_or_title}`、`{family}`、`{year}`、`{part}` 和 `{ext}`。每次先“预览计划”，检查数量、目标和冲突，
再显式确认执行。媒体目标永不覆盖；已有 NFO 可选择覆盖、跳过或报错。NFO 通过临时文件原子替换，
内容兼容 Kodi、Jellyfin 与 Emby 常用 movie NFO 字段。

非 JAV 使用更严格的本地准入规则：作品必须来自用户确认的目录演员，或命中维护中的非 JAV 演员目录别名；
演员、分类与作品记录必须相互一致。实体视频还必须先点击“生成非 JAV 截图”，由 `ffmpeg` 在影片中段附近
生成并绑定该文件自己的 `fanart.jpg` 和 `poster.jpg`，缺图时不会进入任何整理计划。`.strm` 只保存远程
媒体地址，无法可靠截帧，因此免截图，但仍要求有效地址、明确演员和正确分类。未通过的条目继续留待确认，
不会因为顶层目录名是 `Japan`、`国产` 或 `欧美` 而被自动写入作品库。
Docker 镜像已经包含 `ffmpeg`；直接在 Windows/macOS/Linux 本地运行时，需要让 `ffmpeg` 位于 `PATH` 中。

整理器识别 `CD2`、`PART2`、`v2`、`-B` 和番号后的尾部单数字分片；模板未使用 `{part}` 时会自动在
目标视频名追加 `-CDn`，避免多段落到同一文件。媒体同目录的 `.srt`、`.ass`、`.ssa`、`.vtt`、`.sub`
按番号和分片配对，并使用相同的移动/复制/链接方式。无番号的 `Dragon_1`、`Dragon_2` 不会被误认为同一作品分片。

## 按番号建档与图片

“作品库”页可以直接输入番号查询，不要求先扫描本地视频。媒体库页也可批量识别扫描得到的番号，同一番号的
分集只请求一次来源。精确同番号的多个来源会聚合成一个作品：主结果提供
标题等标量，其余来源补齐剧情、日期、片商等空字段，并合并演员、标签和图片；标量字段来源保存在数据库中。

普通 JAV 会并发查询 R18.dev、FANZA、JavLibrary、MGStage、JavDB、JavBus、Jav321、AirAV、AVSOX
和 FreeJavBT 元数据；FC2 会额外查询 FC2Club、FC2Hub、官方 FC2 Contents Market 与 Paipancon。站点受到地区限制、Cloudflare、登录或临时网络故障时，
来源诊断会单独标记失败，其他来源仍继续工作。所有来源只查询番号、文本或用户指定 URL，不使用截图或图片反搜。

作品首次正式识别后会缓存公开图片；也可点击“缓存图片”，整理预览会补齐尚未下载的图片。图片按作品独立存入
`data/artwork/<作品ID>/poster.*` 和 `fanart.*`，不会跟随媒体质量版本重复下载。缓存
只接受常见图片 MIME，单图默认最大 25 MiB，并拒绝 localhost、私网 IP 和 `.local` 地址。整理时图片统一写为
`poster.jpg/png/webp` 与 `fanart.jpg/png/webp`；来源只有一张封面时会同时作为 poster 和 fanart。已有图片默认跳过。

## 标题翻译

新识别的日文、英文和韩文作品会自动把展示标题翻译为简体中文。作品库的“补翻译标题”可为已有作品批量补齐。
翻译前标题保存在 `original_title`，来源快照保持原样；NFO 同时输出中文 `<title>` 和原文
`<originaltitle>`。相同原文使用 `data/translations.db` 缓存，重复刷新不会再次请求翻译服务。

默认使用 Google Translate 公共端点，并沿用服务端代理设置。翻译失败不会撤销识别或覆盖原文。可通过环境变量关闭
或替换端点：

```dotenv
SHADOW_MDC_TRANSLATION_ENABLED=true
SHADOW_MDC_TRANSLATION_ENDPOINT=https://translate.google.com/translate_a/single
SHADOW_MDC_TRANSLATION_TARGET_LANGUAGE=zh-CN
```

启用后，待翻译标题会发送到配置的翻译服务；不希望发送时应关闭该开关。

## 在线来源与代理

“在线来源诊断”会用一个已知番号实际请求各个已配置来源，区分成功、无结果、连接超时、HTTP 拦截和未配置。
若所在网络无法直连 JavDB/JavBus，在 `.env` 中配置代理并重启：

```dotenv
SHADOW_MDC_PROXY_URL=http://127.0.0.1:7890
SHADOW_MDC_REQUEST_TIMEOUT_SECONDS=20
SHADOW_MDC_REQUEST_RETRIES=1
```

代理地址只从服务端环境读取，不通过浏览器或诊断响应回传。重试仅用于连接错误、超时、429 和 5xx；来源失败
不会覆盖本地已识别作品。

## 运行记录

“运行记录”保存最近的扫描、番号查询、图片缓存和批量整理结果，包含处理范围、成功/部分完成状态、数量统计和
完成时间。当前是同步操作的持久审计历史，不冒充后台队列；页面请求关闭时不可依赖它继续执行。后续后台 Worker
会沿用同一任务实体增加阶段进度、重试与取消。

## 数据边界

Shadow MDC 只管理用户已有本地媒体的元数据与公开图片，不提供影片下载、磁力搜索、破解、登录绕过或在线播放。
