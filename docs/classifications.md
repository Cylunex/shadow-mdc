# 多维分类与数据迁移

分类按维度组织，每个分类项都有永久 ID、展示名称、搜索别名和修订号。它与作品通过正式关联表连接；
修改名称不改变作品关联、筛选和动态片单。主题标签继续保留来源词，作为更细的内容特征入口。

| 维度 | 用途 | 示例 |
| --- | --- | --- |
| 内容体系 `contents` | 内容所属体系 | JAV、国产原创、欧美内容、动画内容 |
| 作品类型 `types` | 作品大类 | 电影、剧集、动画、纪录片、综艺 |
| 题材 `genres` | 内容题材，可多选 | 剧情、喜剧、悬疑、爱情 |
| 表现形式 `forms` | 呈现形式，可多选 | 长片、短片、合集、自拍、VR |
| 音轨语言 `languages` | 实际使用的语言 | 中文、粤语、日语、英语、无对白 |
| 字幕语言 `subtitle_languages` | 字幕提供的语言 | 中文、日语、英语、无字幕 |
| 制作地区 `regions` | 明确的制作国家或地区 | 日本、中国大陆、美国 |

年代继续由发行年派生。演员、机构、系列、播放状态与主题标签仍可组合筛选。
同一维度的多项选择采用“任一匹配”，不同维度采用“同时匹配”。

没有明确分类的维度显示“待补”，可以直接筛选。内容体系在没有人工指定时由作品的来源体系 `family` 派生；
人工指定优先，清空后恢复派生。来源分区 `Work.category` 继续用于既有识别和文件库路由，不能等同制作地区。
音轨语言、字幕语言、类型和制作地区不会从标题、来源体系或分区猜测。

## 数据模型与操作

- `catalog_classification_terms` 保存分类项：ID、维度、名称、归一化名称、别名和修订号。
- `work_classifications` 保存作品与分类项的关联，主键防止重复关联，按分类项建立反查索引。
- `work_taxonomy` 只保存人工发行年，分类不再保存为该表的字符串数组。
- 初始词典在 `src/shadow_mdc/classifications.py`，首次启动填充缺少的分类项；已修改的名称不会被启动种子覆盖。
- 分类浏览可切换各维度、年代和主题标签，按名称及别名搜索、按作品数排序，也可新增或改名分类项。
- 作品列表的组合筛选、作品详情与编辑表单共用这些分类项。选择、链接与片单存储 ID，界面显示名称。
- 分类项改名使用修订号检测并发修改；同维度名称与别名不允许歧义。新增自定义项的 ID 与名称无关。

## 一次性迁移

数据库初始化时，在同一事务中把旧 `work_taxonomy.genres/forms/regions` 数组迁入分类关联表。
已知名称与别名归并到预置 ID；未知名称创建正式自定义项，保留原展示名称，重复大小写写法归并。
迁移同时把服务端动态片单中的旧分类条件转换为 ID，保留其它条件和人工发行年。
浏览器本机保存的分类筛选在首次加载时一次性转换为 ID；未知分类项先正式创建，迁移成功后更新本机保存结果。
逐项核对迁入的作品关联后删除旧列；数据格式错误或引用缺失时回滚，不删除来源列。
迁移可重复执行，数据库继续使用同一作品 ID；运行时接口不再接受旧分类名称作为筛选值，也不保留旧列双写。

迁移随服务启动执行，发布前按运维约定备份并验证数据库。代码测试使用隔离数据库，不直接修改运行中的片库。
旧 URL 中的分类名称不作兼容，新的链接和筛选使用正式 ID。

## 接口

- `GET /api/catalog/classifications`：维度、全部分类项、名称、别名、修订号和作品计数。
- `POST /api/catalog/classifications/terms`：新增分类项。
- `PUT /api/catalog/classifications/terms/{id}`：修改展示名称与别名，携带当前修订号。
- `GET/PUT /api/catalog/works/{id}/taxonomy`：读取或编辑作品分类；数组只接受本维度的正式 ID。
- `POST /api/catalog/works/query` 和 `/facets`：组合筛选及分类统计。
- 移动端 `/api/media/v1/catalog` 提供同样的分类读取与筛选，沿用移动访问令牌，不开放编辑。

名称修改、并发修订冲突、移动读取及页面交互。
