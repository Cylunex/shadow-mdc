# Shadow MDC 架构

## 核心实体

- **Work**：一个逻辑作品或场景。内部 UUID 是唯一身份；主番号可空。
- **MediaAsset**：本地视频文件或 `.strm` 引用文件。资产可未识别，也可多资产关联同一 Work；分辨率、编码、码率、HDR、音轨和实际时长只属于资产。
- **ExternalIdentity**：Work 的多值身份，按 provider、kind、规范化 value 唯一。
- **Actor / WorkActor**：演员是独立实体，`work_actors` 保存 Actor 与 Work 的多对多关系及演职顺序；`Work.actors` 只保留为兼容字段。
- **MatchCandidate**：provider 返回但尚未被用户或阈值接受的候选。
- **SourceSnapshot**：某来源一次返回的原始结构化字段，用于追溯与重新聚合。

演员、片商、标签不承担作品身份。演员使用正式多对多关联，同一演员可以关联多部作品，一部作品也可以关联多位演员。
Work 保存稳定的作品标题、剧情、演职员、发行信息和图片引用，不保存某个文件版本的画质。相同作品换成更高质量
文件时只更新 MediaAsset 技术信息；标准番号命中已有 ExternalIdentity 后直接复用 Work，不再请求远程来源。

## 识别流程

```text
文件扫描
  → 提取 code / title / URL / hash / 文件技术信息 / 主分类 / 目录别名线索
  → 暂存 local-path 候选，通用文件名按最近有效目录生成分集线索
  → 根据内容族与查询能力选择 providers
  → 并发获取候选
  → 确定性证据和相似度评分
  → 有番号：高置信自动接受 / 其余待确认
  → 无番号：高置信在线接受 / 否则接受本地优化记录
  → 保存 Work、Identity、Snapshot
  → 对展示标题做机会主义中文翻译，原文快照不变
  → 生成 NFO、图片与整理计划
```

内容族只决定路由，不决定身份。国产内容不假定有稳定番号；欧美内容优先指纹、provider ID 和 URL；JAV 优先规范化番号。
主分类按资产自动推断，优先级是已识别身份/番号、明确目录关键词、文字脚本、媒体库名称兜底。长账号名和编码器名称
不会被通用 JAV 正则当成番号；但目录位于国产库时，真正的标准 JAV 番号仍优先归入 Japan/JAV。

`local-path` 使用媒体库 ID 与相对路径哈希作为候选外部 ID。标准番号按规范值批量去重查询，在线精确候选达到
阈值后才创建或关联 Work；失败继续处于审核状态。无番号按优化标题搜索，若无可接受在线结果，则把
`local-path` 候选显式标记为 accepted 并创建本地 Work，因此仍具有可审计的决策记录。

`.strm` 是本地 sidecar 资产：扫描器只读取首个有效媒体定位符，不请求远程媒体，也不对其执行
ffprobe 或 oshash。定位符只用于补充文件名线索；持久化前移除 URI 用户信息、查询参数和片段，原始内容仍只存在于用户的 `.strm` 文件中。

实体媒体通过 ffprobe 生成独立的 `MediaTechnicalInfo`，包含容器、视频/音频编码、分辨率、帧率、码率、位深、
声道、采样率、HDR 和质量标签。NFO 的 `fileinfo/streamdetails` 来自当前 MediaAsset，作品字段仍来自 Work。

无番号文件优先使用非通用文件名；`01`、`video` 等通用名称会回退到 `.strm` 目标文件名和最近三级目录。
别名规则形成片商、系列和人物证据，不作为远程作品身份。旧作品的演员数组会自动回填到 Actor/WorkActor；演员作品索引从多对多关系与用户别名构建；
下一轮扫描把规范演员名加入别名规则，使目录人物名进入 `IdentityHints.actors`，参与在线评分和本地规范化。

## 文件系统边界

扫描器逐目录枚举且不跟随目录符号链接。共享目录中的单个子目录断线或无权限时记录错误并继续扫描其余内容。
网络路径必须由运行 Shadow MDC 的操作系统或容器提前挂载；扫描只要求读取权限，整理和 NFO 写入要求目标目录写权限。
硬链接仍受同卷约束，跨卷或不支持硬链接的网络文件系统会明确失败。

支持的媒体扩展名在提取身份和探测媒体前经过路径过滤。过滤规则是普通字面量，不执行用户正则或代码；规则匹配
媒体库相对路径并对 Unicode 做 NFKC、大小写和空白归一化。过滤仅阻止新资产入库，不对磁盘执行删除或其它写操作。

## 来源边界

Provider 是无状态适配器，只接收 `IdentityHints`，返回 `ProviderRecord` 列表。它声明查询模式、内容族、认证和交互要求。Provider 不接触数据库和文件系统。

标题翻译位于来源聚合之后，不属于 Provider。译文只写 Work 展示字段，原文保留在 `original_title` 与
`SourceSnapshot`；失败时保留原文继续完成识别。翻译缓存按原文、目标语言和字段哈希，独立存放在
`translations.db`。

公开图片按 Work UUID 存入 `data/artwork/<work-id>/poster.*` 与 `fanart.*`。首次正式识别后下载，后续扫描和
质量替换复用原图；前端通过受控 API 展示缓存图片，演员库同时展示演员代表图和关联作品海报。整理计划只在需要输出 sidecar 时把中央图片复制到作品目标目录。

内置首批来源：

- JavDB：JAV 综合搜索与详情。
- JavBus：JAV 番号与图片补充。
- Jav321：JAV 番号详情、演员、标签与封面补充。
- ThePornDB：需 Token 的场景/JAV/指纹联邦源。
- JSON-LD URL：用户指定详情页时提取标准结构化数据，服务非常见影片。

## 安全整理

整理器先生成 `OperationPlan`。计划包含来源、目标、冲突、动作和摘要哈希；执行端必须提交同一哈希。
原目录模式只写作品目录中的 `movie.nfo` 和图片；复制、移动和链接模式的目标必须落在用户显式选择的目标根目录内。
媒体目标默认不覆盖，批量流程逐项记录失败，路径或模板变化会令旧计划失效。

## 验收范围

- 规范 JAV 番号可自动识别并生成 NFO。
- 无番号文件先按标题或 URL 搜索，未命中后形成可审计的本地优化作品。
- `.strm` 可被索引，远程地址不会在扫描阶段被访问，敏感查询参数不会写入数据库。
- 映射盘和 UNC 共享可扫描；局部目录错误不终止整次扫描。
- 欧美场景可用 oshash 或 ThePornDB ID 匹配。
- 同片多号合并为一个 Work。
- 来源失败不会阻断其它来源；所有失败可诊断。
- 文件操作未经计划确认不会发生。
