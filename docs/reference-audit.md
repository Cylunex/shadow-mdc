# 参考项目功能审计

本审计基于本地参考仓库中的 JavSP、JavSP-Web、MDCX、MDC-NG、Amane 与 Peach。
Shadow MDC 只吸收行为、边界和使用流程，所有代码、模型、接口与测试均独立实现。

## 项目观察

| 项目 | 值得吸收 | 需要避免 |
|---|---|---|
| JavSP | 多站并发、按内容类型路由、字段汇总、分片、封面与 NFO、可配置命名 | 同步 CLI 流程、站点逻辑与文件操作耦合、失败后人工流程不足 |
| JavSP-Web | 持久任务、阶段进度、预设、定时刮削、Cookie 同步、下载器和媒体服务器联动 | 把配置文件直接当业务模型、默认账号和高权限集成混在主流程 |
| MDCX | 来源覆盖广、国产/FC2/素人分流、字幕、演员、图片标签、软链接 | 大量站点特例堆叠、设置项过密、旧架构技术债 |
| MDC-NG | 原地/复制/移动/硬链/软链五模式、监控兼容模式、任务详情 | 本机副本只有 README 与静态资源，无法把宣传项当作已验证实现细节 |
| Amane | 数据库真值、多源字段来源、资源物化、任务图、HTTP 缓存/限流、插件边界 | 直接复制其源码或模型；过早引入 AI 助理和复杂插件运行时 |
| Peach | 稳定身份续播、已有预览复用、查询共享、任务后继、文件写入收口 | 把完整播放中心与资料实体系统搬入刮削工具；仅靠缓存掩盖慢查询 |

## 实施顺序

1. 先保证识别、聚合、图片、NFO 和文件整理闭环可靠。
2. 再把长操作迁入持久任务，增加进度、重试、取消和运行历史。
3. 增加监控/定时、媒体服务器刷新与人物资料。
4. Provider 契约稳定后扩展来源和插件，不以“来源数量”代替可测试性。

## 2026-10-27 整体复查与独立改进

本轮核对官方文档和上游项目说明，并对照本仓库现有实现。以下“落地”是 Shadow MDC 自己的
设计与实现，不表示上游使用相同算法，也未复制上游源码、配置或界面。

| 一手参考 | 观察与本项目取舍 | 本轮落地 |
|---|---|---|
| [JavSP](https://github.com/Yuukiy/JavSP)、[Javinizer Go](https://github.com/javinizer/javinizer-go/blob/main/docs/01-getting-started.md) | 多源查询、聚合和缓存比单纯扩大来源数更重要；沿用已有路由、字段锁和来源快照 | Provider 增加整次调用截止时间；超时仍保留其他来源结果，排队后再次检查冷却状态 |
| [Stash 元数据来源](https://docs.stashapp.cc/metadata-sources/) | 指纹、来源 ID 与名称承担不同匹配作用；本项目不把同名当作品身份 | 无番号 NFO 优先复用来源 ID，没有来源 ID 时按 sidecar 路径生成身份，避免同名误合并；标题编辑不会换身份 |
| [tinyMediaManager 设置](https://www.tinymediamanager.org/docs/movies/settings) | 媒体信息与作品元数据分离，重复扫描应复用已有技术信息 | 保持按大小和修改时间复用探测；ffprobe 超时、异常输出和非有限数值不会中断扫库，跳过内嵌封面流 |
| [Jellyfin NFO](https://jellyfin.org/docs/general/server/metadata/nfo/)、[影片组织](https://jellyfin.org/docs/general/server/media/movies/) | 本地 NFO、来源 ID、同名 sidecar 和字段锁需要互操作；本项目选择更具体的 sidecar 优先 | 同名 NFO/海报优先于目录默认；IMDb ID 不再误判为 JAV；兼容嵌套 set/name、Runtime 锁、演员和标签去重 |
| [beets 导入](https://docs.beets.io/en/stable/reference/cli.html#import) | 增量与重试应保护已有工作；不引入第二套自动整理流程 | 保留逐文件增量规则，目录枚举和分片分析阶段也检查取消；沿用已解析根路径，减少逐文件 resolve |
| [hls.js 生命周期](https://github.com/video-dev/hls.js/blob/master/docs/API.md) | 媒体绑定和释放必须配对；异步加载完成不等于旧视图仍有效 | 切片/卸载后忽略迟到回调，销毁旧 HLS 并释放 video；更换作品重置选源；脚本失败可重试 |
| [HTTP Retry-After](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after) | 尊重上游要求的等待时间，避免限流时反复请求 | 429 和带 Retry-After 的 503 进入来源冷却，支持秒数与 HTTP 日期，不触发额外传输回退 |

任务中心还修复了初始 SSE 信号被清除、线程通知未安全唤醒、每帧重连和断连后没有实际轮询的问题。
前端增加了封面换图后的错误状态恢复，图片预览支持关闭按钮、焦点限制与恢复、键盘事件隔离和索引收缩。

### 回归与保留边界

- `tests/test_reference_improvements.py` 使用本地 NFO、模拟 ffprobe、HTTP MockTransport、事件和短截止时间
  覆盖身份、探测、取消、限流、截止时间与 SSE；不会访问真实来源或修改用户媒体。
- 前端测试覆盖任务连接复用、断连轮询、慢请求互斥、播放器异步清理、换源和图片预览。
- 旧 STRM 回归用例更新为明确的片商/编号目录断言，并用相对当前时间的签名有效期代替过期的固定日期。
  没有放宽迁移冲突、幂等写入、路径通知和缓存命中的断言。
- 本轮不新增来源、不重写来源抓取逻辑、不自动整理既有媒体、不变更生产配置或部署。
- 扫描的独立 Worker、持久任务队列与事务分段仍是后续架构项；本轮没有把这些能力标为完成。
  已误合并的旧 NFO 作品也不会被自动拆分，避免破坏用户整理结果。

本轮验证结果：Python 全量 758 项、前端离线回归 21 项通过；前端类型检查和生产构建通过。
本轮涉及的 5 个后端核心模块与新增测试通过 Ruff 和严格 mypy。全仓库仍有其它文件的历史静态检查
问题，本轮未做无关的批量格式化。

### 本轮实现边界与验收

- 续播保留最近 200 个作品，90 天后过期；校验非有限值、过短位置和媒体时长。
  存储禁用、额度不足或内容损坏不阻止播放；媒体元数据尚未加载时离开不覆盖旧进度。
  先保存并解除监听再释放媒体，避免换源时的归零事件写坏记录；播完移除续播点。
- 偏好写入的失败继续返回原异常，不吞掉失败，也不把旧文件清空。沿用既有 JSON 格式和权限，
  无须迁移；真实运行文件不进入 Git。
- 回归覆盖跨作品隔离、签名地址刷新、自动/手动换源的位置优先级、播完、离页保存、写入节流、
  存储异常、容量与过期，以及多实例并发偏好更新、原子替换失败和文件权限。
- 本轮没有测量生产首屏耗时，不能把续播与写入可靠性改进计作页面加载提速。
  页面加载下一阶段优先统一查询与失效，并按路由分别记录无缓存首屏请求数和响应时间。

验证：Python 全量 770 项、前端 39 项通过；前端类型检查与生产构建通过。
本轮偏好模块与新增 Python 测试通过 Ruff 和严格 mypy；不表示全仓历史静态检查问题已清理。

## 共享查询与冷加载的后续落地

继上述 Peach 对照后，已将共享查询从候选项落到代码：全站唯一 QueryClient 与资源定义，
影片、演员、分类、详情、任务与离线状态共用资源查询；并发读取合并，写入按资源失效。
保留 MDC 的无路由预取结构，组件直接渲染已有数据；参考项目关闭挂载重取的设置不直接照搬。

本次重点是减少缓存为空时的工作：移除所有页面启动时的任务历史与媒体库配置读取，外站刷流不
预取全库；演员目录与设置状态独立显示，详情主体先于可选请求。设置、榜单、订阅另按需下载代码。
“想看”写入与背景任务完成都更新共享资源，不通过全局刷新反复下载整库。
