# 统一作品、人物、机构与播放

作品、演员和分类浏览使用同一片库，查询条件可组合。年代按发行年派生，类型、题材、地区保存明确资料，标签保留来源词。人物主名、作品编号和机构显示名都可以调整，已有作品 ID 和 Emby 绑定继续对应原实体。

标签通过固定 ID 参与筛选、统计和片单，展示名称与来源别名单独维护；旧名称链接继续兼容。详见[标签标识与展示](tags.md)。

## 演员档案与迁移

首次读取目录会把数据库演员、持久演员目录和人工人物档案导入 catalog_people，catalog_person_references 保存旧引用。
导入可重复执行，同名记录独立保存，零作品档案及私有备注、目录匹配词、头像引用均保留。源表与旧配置作为兼容输入。
SQLite 源版本触发器与配置文件修改时间用于失效判定，已导入的数据无需在每次浏览时重新逐条写入。

演员库支持主名/别名搜索、关注筛选、按姓名或作品数排序、资料编辑、头像上传、参演与执导关联、合作人物与机构浏览。
人工字段独立保存，识别任务可读取规范人物的别名和目录识别词。
旧引用和已合并 ID 都可解析到规范档案；旧订阅仍使用原引用。
手机接口隐藏私有备注及目录识别词，头像通过带移动令牌的接口读取。

合并在当前页面确认，原记录继续保存，日志记录参与者和修订号。撤销可重复调用，连续合并可按相反顺序撤销。
合并后出现新的资料修订时，撤销返回冲突，防止覆盖后来的编辑。
人物新增、改名和合并都不以姓名作为数据库身份。

管理端 GET /api/catalog/migration 返回人物、作品、播放绑定数量及本次新增人物数。
迁移记录长期保留在数据库，业务文件和原目录无需重命名。

## 机构、系列与片单

机构可以独立于作品创建，保存别名、简介和所属机构。
作品关系明确区分制作、发行、厂牌、平台、系列与原始署名。同一作品参与多个角色时按作品 ID 去重。
机构层级拒绝循环，修订号保护并发编辑。旧 Collection ID 继续可用。

片单保存手选作品及顺序，支持添加、移除、调整次序及改名，保存时检测版本冲突。
服务器用 X-Catalog-Owner 标识偏好空间，浏览器自动生成片单标识。
在 Media 添加或编辑 MDC 连接时填写相同标识，可使用同一片单空间。
这个标识用于内容偏好分组；服务访问仍由原有 Web 登录和移动端令牌控制。
移除片单只移除这份整理关系。

保存的筛选可以留在当前浏览器，也可以在「我的片单」中用当前筛选创建动态片单。
动态片单随入库和资料变更更新成员，Media 用同一片单标识即可读取当前结果。
在 Web 可应用、替换规则或改名。手选片单仍支持单部作品排序。
人工片单固定成员，筛选方案由条件生成结果。手机提供演员、年代/年份、机构、题材、形式、地区、标签、状态和片单入口。

## 在线播放和恢复

详情首屏提供播放入口。Media 优先打开精确 Emby 条目；已有 Emby 绑定异常时保留该选择，用户可显式打开在线版本列表。
在线源先校验完整作品编号，再验证 HLS 清单或 HTTP 视频前缀。
格式随候选返回，无后缀 HLS 可由浏览器和 Media3 正确选择加载器。
HTTP 视频支持 MP4、WebM、MKV 候选，网页动作保留明确跳转语义。

版本身份包含来源条目和来源提供的分片线索。签名变化或分片重排后，续播仍对应同一分片。
无法确认同一时间轴的资源分开保存进度。
Web 在引擎恢复失败后最多重解当前线路一次；Media 在现有播放器重试耗尽后，按当前播放会话的作品与版本重解一次。
新的候选必须匹配当前版本，失败后保留进度并显示重试或选线入口。
Emby 继续使用实际播放账号的进度，其他线路使用连接与版本对应的本机历史。

Web 的“按当前筛选刷片”继承条件、排序和结果队列，可继续追加同一查询的后续页。
切片取消旧解析，追加分页保留当前播放，离开页面取消未完成加载，返回恢复筛选与位置。
独立外站刷流继续使用独立条目身份。

## 用户验收

真机播放由用户验收，自动回归使用隔离数据库、HTTP fixture 和 Android JVM 环境。

1. 从演员档案筛选工作室，打开影片并播放 Emby，退出后核对账号续播及原筛选。
2. 使用旧演员链接、同名演员和零作品档案，确认各自资料及合并/撤销结果。
3. 创建片单并调整顺序，在 Media 连接中填写同一片单标识，核对成员和顺序。
4. 用本地配置的在线来源播放 HLS 和 HTTP 视频，验证首帧、Seek、字幕及退出续播。
5. 使签名过期，确认只重解一次且保持同版本位置；换到 CD2 或不同剪辑时核对独立进度。
6. 检查无权限账号、断网、没有来源及所有线路失败时的操作提示。
