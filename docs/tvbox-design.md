# MDC 接管 TVBox 源管理与 Shadow Media 点播设计

2026-11-20 · 设计稿。TVBox 的源、更新任务、体检、编排、订阅发布和回滚全部归 MDC。Relay 只参与一次性数据迁移，目标运行形态是 MDC + Media。

**日常使用只有一次提交。** 在 MDC 的「TVBox」粘贴源地址或导入文件，点「导入并测试」。通过的站点立即出现在当前页面和 Media；多站配置逐站生效。用户可以直接点影片播放。失败项在原处显示原因，修改地址后可单独重试。Media 下次打开目录或刷新即可看到新增站点。

## 首批实现

MDC 的「TVBox」已经支持 URL、JSON/JSONC 文件和多仓导入。后台测试逐站提交，Media 刷新即可看到通过的站点。支持 type 1 分类、翻页、检索、选集和 HLS/MP4 解析。站点启停、重新测试、优先级和分类快照回滚在 Web 源管理完成。URL 配置每天直接复查原始上游，文件导入的站点每天测试 CMS 端点。失败修订保留上一可用分类快照。播放地址在选集时重新获取。Losna 可通过 mdc-operator 的 tvbox.import、tvbox.status、tvbox.sources 和 tvbox.sync 使用同一套接口。

Media 用既有 MDC 连接识别 `tvbox_v1`，沿用原生播放器。观看记录保存在 Media，通过站点、影片和分集线路 ID 重新解析。移动 API 仅开放浏览和解析。Web 直接播放取决于源站允许浏览器读取流，带特殊播放头的线路优先通过 Media 播放。

Relay 数据的首批迁移使用 `uv run python scripts/prepare_relay_tvbox.py PRIVATE_EXPORT PRIVATE_OUTPUT`。工具接受 v1 导出归档或其 manifest，只取已启用源包的生效 type 1 站点，生成权限为 0600 的 JSON 文件。把文件交给同一「导入并测试」流程即可，运行时不需要 Relay。本机用临时数据库对从 Relay 提取的 29 条 type 1 站点做实网复测，3 条通过分类、详情和媒体响应检查。未启用项保留具体失败原因。

下文还记录完整接管目标。历史修订、旧分组和绑定迁移、第三方订阅发布、type 0 和生产切换属于后续交付。

## 从哪批数据开始

通过 Relay 只读 API 盘点了当前源库、生效修订、TVBox 聚合入口及其中由 Relay 托管的子配置。下表为当日快照。

| 盘点对象 | 实测结果 | 对首版的意义 |
| --- | --- | --- |
| TVBox 源库 | 23 个源包全部启用，均有 activeRevision，其中 15 个另有 stagedRevision | 追溯来源时固定生效修订，待生效修订单列 |
| 生效修订的 normalized.items | 32 条 site，按 API 地址去重仍为 32；其中 type 1 有 29 条、type 0 有 3 条。另有 41 条 store、95 条 live | 源包、站点和直播引用分别计数。站点需要进一步验证协议与内容策略 |
| aggregate-tvbox 当前发布 | store.json 有 52 个引用。其中 1 份 Relay 托管的子配置给出 20 个不同 API，均为 type 1。其余 51 个引用此次只计数 | 20 条用于验证既有发布效果；接管范围覆盖源库的全部源包。其余引用的内容、重叠及有效性待分类 |
| Relay 种子目录 | TVBox 候选文件内有 5 个不同的种子 URL | 留作后续补充来源，不能与发布条目相加计算可用率 |

本次核对到配置层。站点分类、影片详情、线路、首帧均待实施时抽检。32 与 20 属于不同集合，不能据差值判断其余站点失效。站点链接、订阅令牌、原始响应和站点分类映射只进私有运行数据。

## 接管后的职责

| 项目 | 已有能力 | 本次设计 |
| --- | --- | --- |
| Relay | TVBox JSON/JSONC、多仓、版本、发布与订阅。CMS site 的播放需要下游运行时 | 一次性提供源和管理状态，迁移后退出运行链路 |
| MDC | SQLite 片库、Apple-CMS 按番号找片、分类策略、HLS/视频探测、移动端能力发现与播放计划 | 持有源库和订阅发布，直接向原始上游更新；按站做分类、检索和详情解析，发放短时播放描述符。站外条目按需缓存，浏览不会写入正式作品库 |
| Media | 手工 TVBox 源已有 ExternalSources 和 TvBoxHttpMediaProvider，支持 JSON 目录和原生播放；MdcMediaProvider 已有移动鉴权、统一账号桥接和带前缀的 API | 在现有 MDC 连接下注册托管目录，共用播放器、搜索开关和会话。用户手工加的源保留原入口和历史 |

Relay 的依据是 adapter、publisher 及 client-contract，核对了本地检出 8ff41f0 和远端跟踪版本 e3095da，并以实际发布物校正数据范围。MDC 基线 64cf22d，Media 基线 845929c。现有作品播放继续优先精确 Emby 条目，TVBox 从独立在线目录进入。后续若要给本库作品补线路，复用已有身份匹配和人工绑定，仅用片名命中时保留候选。[MDC 播放服务](../src/shadow_mdc/services/playback.py) · [移动端契约](media-client.md)

### 参考项目怎样影响设计

- FongMi TV 把分类、详情和点播分开。详情可返回多个播放分组，用分集 ID 在播放时取地址。MDC 据此保留“站点 → 条目 → 分集 → 线路”层级，Media 切换分集时取消上一次解析。[FongMi 官方协议与示例](https://github.com/FongMi/TV/blob/fongmi/website/app/spider/page.tsx)
- Stremio 的 stream handler 按内容类型和视频 ID 返回流候选。MDC 也只在选集后生成候选，列表翻页不探测整页视频。[Stremio SDK 播放接口](https://github.com/Stremio/stremio-addon-sdk/blob/master/docs/api/requests/defineStreamHandler.md)
- Kodi 分别提供目录回调和 setResolvedUrl，后者可显式表示解析失败。Media 保留当前详情和集数，某线路失败时可在原位置重试或换线。[Kodi 插件接口](https://xbmc.github.io/docs.kodi.tv/master/kodi-dev-kit/group__python__xbmcplugin.html)

## 谁来管理源

| 用户操作 | MDC 的行为 |
| --- | --- |
| 导入 URL、JSON/JSONC 文件或多仓目录 | 一次提交创建或复用任务，自动展开、去重和测试。合格站点立即启用，进入默认分组，自动刷新 Media 目录和已绑定的 TVBox 订阅。重复提交可直接打开已有结果 |
| 查看结果或重试 | 同页显示“可使用 / 检测中 / 失败或不支持”，成功项可直接浏览或播放测试样片。失败项显示具体环节和重试动作，其他源照常使用 |
| 更新源 | 支持定时抓取和“立即更新”。URL 源直接请求原始上游，文件源保留私有原文并支持导入新版。候选修订通过测试后自动替换生效版本，失败时沿用上一可用修订 |
| 调整源与分组 | 支持改名、排序、主备、固定、隐藏、暂停、恢复，保留个人覆盖。停用立即从目录和当前订阅撤回。用户可主动切回上一可用修订并固定 |
| 使用订阅 | Media 从已有 MDC 连接直接读取。第三方 TVBox 客户端可复制 MDC 签发的多仓订阅；MDC 生成稳定入口及固定版本子配置，并管理绑定范围、过期、轮换和吊销 |

首版管理入口拟用现有 Web 管理会话下的 `/api/tvbox`。一次 `POST /imports` 返回任务 ID 和已确认结果，前端自动读取任务后续结果。源、修订与分组属于 MDC 的持久数据，健康记录关联到具体修订。服务在短事务内提交单站测试结果、当前目录版本和订阅发布指针，避免 Web 已显示可用而订阅仍需人工发布。相同修订重复执行幂等，旧任务晚到时不得覆盖新修订。Losna 通过 mdc-operator 的同一导入、状态、重试能力调用该服务。

**自动测试的通过条件。** 按站识别协议，在配置允许的分类中取得一条真实条目，打开详情，取出一集的一条线路，对 HLS 清单或视频首包做有界校验。通过后目录收录该站，测试条目可直接播放，并记录测试时间。源站暂时超时允许后台重试，协议不支持或没有合规分类直接注明原因。空搜索结果不判整站故障。测试成功代表该站抽样链路成立，其余影片仍在点播时独立解析。真机首帧用于版本验收，日常导入无需人工试播。

内容过滤自动沿用 MDC 既有分类规则和已保存的按站映射，可高置信识别的允许分类自动应用。上游仅给不明分类编号时，单独提示该站缺少映射，不能因此挡住同批已通过的站点。type 1 JSON 优先实现，type 0 XML 入库并保留其原始配置和既有订阅表达，原生点播适配随后补齐。多仓按深度、去重、请求数、体积和超时有界展开。直播引用归为直播，脚本或专用运行时记录其依赖与兼容状态。

## 一次性搬走 Relay 数据

实施时由迁移工具读取同一时点的 Relay 私有导出与必要的只读补充数据，按 TVBox 对象及其关联筛选。接管对象包括所有源包及相关管理记录；已发布的 20 条站点只用于对照结果。停写窗口内完成最终差量核对，只启用 MDC 一侧的定时任务。用户在 MDC 看到的仍是一次导入的结果。

| 旧数据 | MDC 接管方式 |
| --- | --- |
| 源、端点、种子、多仓目录、候选 | 保留可独立刷新用的原始入口或内联文件、归属及候选的接纳/忽略/屏蔽状态。把旧发布路径解析为 MDC 成员引用，原始上游缺失时保留本地快照并标明更新方式 |
| 修订、原始快照、健康与调度 | 保留生效、待生效、固定修订的身份、内容散列、启停和更新周期。待生效数据保留原状态；新导入沿用自动测试规则。体检记录标注来源及时间，未完成的旧任务不重放 |
| 编排组、发布、偏好与绑定 | 保留 TVBox 成员、顺序、首选/备用、过滤、改名、隐藏、当前及上一发布的修订映射。按已安装 Relay 的导出字段核对偏好等扩展数据，缺项从只读接口补齐。仅向仍有效的绑定签发相同或更窄权限的 MDC 订阅，固定版子配置由 MDC 提供，旧客户端一次换址 |
| 网络、凭据及其他领域 | 源依赖的代理和凭据迁入 MDC 私有配置并重新绑定，缺项保留具体原因。小说等其他领域按旧源组和活跃绑定列清单，交由对应领域承接或记录退役决定，再退出整个 Relay 服务 |

旧源 ID、修订 ID、发布 ID 与新 ID 建唯一映射，绑定快照摘要记录一次性迁移批次。重跑复用相同对象和用户覆盖，冲突及未转换项逐项列出。导入先核对全量对象和关联，再原子接管管理数据；后续站点测试各自生效。停用、屏蔽及已撤销绑定保留其限制。原始数据、旧密钥和订阅地址只在私有环境处理，常规启动与更新仅使用 MDC 配置。迁移失败可从一致快照重试，切换后的管理回滚使用 MDC 自有修订。

## 数据身份与用户操作

| 对象 | 建议身份 | 保存与展示 |
| --- | --- | --- |
| 订阅和源包 | MDC source_id；旧 sourceId 存迁移映射 | 保存原始上游、ETag、修订散列、最近成功时间；下游订阅和发布指针独立于源身份 |
| 站点 | 源包内稳定 site.key 映射为 MDC site_id；缺 key 时对规范化 API 建立本地别名 | 改名保留历史。同 key 换站或冲突时重新验证并保留旧映射。同一端点可去重网络请求，成员归属与分类策略分别保存 |
| 站外影片 | site_id + 原始 vod_id 映射到 item_id | 短期缓存详情、海报引用和分类。字符串形式保留前导零；同名跨站并列展示来源 |
| 分集与线路 | 站内条目下持久分配 episode_id、line_id | 优先上游稳定键，其次采用可唯一匹配的季集标记、版本和线路名。线路排序、集序和短时 URL 仅用于展示或传输。匹配不唯一时保留独立版本或让用户重选 |
| 观看进度 | 账号/连接 + 站点条目 + 分集 + 版本 | 同一版同一集的不同线路可续播。剪辑、正片与预告独立记录；应用重启后用 ID 重新解析 |

例如，用户在“线路一”看完第 2 集的前 18 分钟。站点次日把“线路二”排到首位，签名 URL 也变更了。Media 应仍能打开原剧第 2 集并恢复至 18 分钟。若新目录同时出现正片和导演剪辑且无法验证对应关系，则展示两个版本供选择，原记录继续可查。现有 Android 手工 TVBox 的分集键含线路与分集下标，托管目录应使用 MDC 发放的稳定 ID。

## MDC 和 Media 的接口

以下为拟新增契约。移动端前缀沿用 /api/media/v1，通过既有 capabilities.features 宣告 tvbox_v1。旧服务没有此能力时隐藏托管入口。Web 使用当前管理会话，移动端只读目录与解析，两端共用同一服务层。

| 移动端路径（相对前缀） | 输入 | 返回及语义 |
| --- | --- | --- |
| GET /tvbox/sites | 当前连接 | 允许浏览的站点 ID、名称、能力、最近成功时间 |
| GET /tvbox/sites/{site_id}/categories | 站点 | 该站允许展示的分类 ID、名称 |
| GET /tvbox/sites/{site_id}/items | category_id、cursor、limit | items、next_cursor。游标绑定站点、类别和修订，失效提示刷新 |
| GET /tvbox/search | q、可选 site_id、cursor | 分站结果与失败站点。并发和总时长有上限，空命中正常；继续翻页沿各站的进度 |
| GET /tvbox/items/{item_id} | 站外条目标识 | 片名、海报、版本、分集及各集可选线路。返回前重查站点启用和分类策略 |
| POST /tvbox/items/{item_id}/resolve | episode_id、line_id | 同版分集标识、URL、MIME、允许的播放头及可选 expires_at；过期时沿原 ID 重解一次 |
| GET /tvbox/items/{item_id}/image | 同源海报引用 | 复用 MDC 图片鉴权方式，有界读取并验证图像类型 |

以 type 1 适配器分别请求上游分类、按 t/pg 分页、按 wd 搜索、按 ids 取详情。对 vod_play_from 与 vod_play_url 按组解析，处理多线路、单片、缺组名、空集、坏集与相对地址。探测复用现有 HLS 和视频首包校验，支持无后缀且可确认 MIME 的视频。单站失败可重试并保留其他站的结果。返回原因至少区分站点停用、分类受限、分集已变更、协议不支持、资源过期和上游超时。

**Media 交互。** 在「影视 → Shadow MDC → TVBox」默认打开上次站点，可切站、选分类、站内或跨站搜索。点海报打开剧集详情，选集后选线路；只有一个可播选项时直接播放。关闭播放器回到原集，返回列表保留搜索词、页和滚动位置。Media 中沿用手工 MDC 连接或 Novel 统一账号桥接；托管结果加入聚合搜索沿用连接开关，并标出来源。MDC Web 首版提供同一套目录与详情用于运营和选片。

**播放与权限。** MDC 仅接受已登记的站点和条目标识作为解析输入。目录、海报、探测、重定向都执行出站目的地址检查、超时和体积上限。Media 用独立播放器网络客户端直连已确认的 HLS/MP4，允许必要的 Referer、Origin、User-Agent；MDC、Novel 凭据仅发送给各自受信接口。直连不可达时保留当前分集并换可用线路。MDC 的网页刷流代理不作为手机通用媒体代理。短时地址不进入历史、日志或公开夹具。

## 实施顺序与完成条件

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 · 管理接管 | 一次迁移全部 TVBox 管理对象，MDC 独立导入、定时更新、体检、编排、自动发布和回滚 | 实施时依最终快照核对源包、修订、目录成员、例外和绑定。对照原发布的 20 条 type 1；混合导入成功/超时/坏配置各一站，成功项无需再次操作即出现在目录和订阅 |
| 2 · MDC 点播目录 | 分类、分页、搜索、剧集详情、按分集解析、Web 浏览 | 固定电影与多集剧样本；不合规分类不能从详情直达，一条坏线路不影响其他候选。临时地址轮换、线路重排及超时都保留分集身份 |
| 3 · Media 原生接入 | 能力发现、目录和详情、原生播放、历史与同集重解 | 手工 MDC 与统一账号各走一次。真机验证首帧、拖动、切集、换线、杀进程续播及退回列表；旧服务、旧手工 TVBox 历史及 Emby 优先播放走回归 |
| 4 · Relay 退役验收 | 在隔断 Relay 的环境重启 MDC 与 Media，完成管理和播放全链路 | 新增来源、原始上游更新、坏版回退、MDC 订阅刷新、绑定撤回、手机冷启动续播全部通过，核对剩余领域绑定的去向后安排关停 |

首次联调按“源包 → 站点 → 分类 → 条目 → 分集 → 首帧”逐层记数。离线测试使用虚构站点和最小响应，真实样本的验证回执仅保留数量、阶段、失败原因和耗时。实施完成的依据是 Media 真机走通整条链路。
